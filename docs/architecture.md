# 配置中心架构设计

## 目标

配置中心是一个 Go 单体应用，用 PostgreSQL 保存用户、项目和配置数据，提供浏览器 UI、管理 API 和对外配置读取 API。项目侧提供 RSA 公钥，配置中心只保存用该公钥加密后的 `config` 和 `env`，不保存明文配置。

## 边界

- 配置中心自建用户体系：注册、登录、密码哈希、会话和 API Token 全部保存在配置中心数据库。
- auth-limit 不保存配置中心用户信息，也不参与配置中心 UI 的登录。
- auth-limit 只作为配置中心服务端协调层，用于外部读取配置时的限流和服务治理接入。
- 每个注册用户只能管理自己创建的项目。
- 配置中心签发的读取 token 绑定用户；刷新某个 token 只影响对应记录，不影响其它用户或同一用户其它 token。
- 外部调用方拿到密文后，使用自己持有的 RSA 私钥解密。

## 模块

| 模块 | 职责 |
| --- | --- |
| 配置加载 | 读取 `.env` 和系统环境变量，生成数据库、会话、auth-limit 配置 |
| 数据库初始化 | 幂等创建专用数据库和专用用户，成功后不再依赖 PostgreSQL 管理员凭据 |
| 数据库迁移 | 创建配置中心业务表，保证迁移可重复执行 |
| 用户与会话 | 本地注册、登录、登出、密码哈希、会话 cookie |
| API Token | 使用配置中心账号密码签发 `access_token`/`refresh_token`，支持按记录刷新和吊销 |
| 项目管理 | 项目 CRUD、项目编码唯一性、用户资源隔离 |
| 配置管理 | 保存项目 RSA 公钥，加密写入 `config` 和 `env` |
| auth-limit 客户端 | 首次 operator 引导、幂等服务注册、服务端限流校验 |
| Web UI | 注册登录、项目列表、项目详情、配置维护 |
| 对外 API | 返回加密后的配置，并在返回前完成 auth-limit 鉴权和限流 |

## 典型流程

### UI 管理流程

1. 用户在配置中心注册账号。
2. 用户登录后获得配置中心本地会话 cookie。
3. 用户创建项目并填写项目 RSA 公钥。
4. 用户保存 `config` 或 `env` 明文。
5. 服务端立即用项目 RSA 公钥加密，只把密文写入 PostgreSQL。

### 外部读取流程

1. 调用方请求 `/api/public/projects/{code}/config` 或 `/api/public/projects/{code}/env`。
2. 配置中心读取调用方传入的 `Authorization: Bearer <ACCESS_TOKEN>`。
3. 配置中心在本地校验 access token，并确认 token 所属用户拥有该项目。
4. 配置中心调用 auth-limit 限流校验接口。
5. 本地鉴权、项目归属和限流都通过后，配置中心返回项目配置密文。

## 安全原则

- 数据库不保存配置明文。
- PostgreSQL 管理员凭据和 auth-limit 管理员凭据只用于首次引导，初始化成功后从 `.env` 清空。
- 日志不输出密码、Token、Secret、私钥或配置明文。
- 会话 cookie 使用 `HttpOnly` 和 `SameSite=Lax`。
- 管理 API 必须校验本地会话。
- 项目、配置和 UI 页面必须校验资源归属。
- 对外读取接口不接受本地 UI 会话作为调用凭据。
- 对外读取接口不暴露 auth-limit 账号、APP Secret 或签名细节。
